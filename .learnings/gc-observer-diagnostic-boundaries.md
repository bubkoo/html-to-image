# GC 观察者诊断边界

901c4bc 与已通过 PR 受测合并树完全相同，主分支仍有三个 Firefox 和一个 WebKit 生命周期失败。已独立验证的回收请求同步缺口不足以解释所有失败，不得以 PR 通过代替 master，也不得重跑后覆盖原失败。

辅助观察先冻结原三次回收的结果，再比较原生/库 owner、计时器和 await/weak-Promise/清空局部变量形式。额外诊断回收不能替换主断言。强持有对象、简单对象 canary、源字体与 frame 清理都是配对控制；只记录纯值，避免诊断自己持有 Document。Mac 的12测试、9原始采样、60辅助观察全过不构成Linux根因。

生产代码未改，分支推送触发器和始终记录标志属于临时排查，合入前必须去掉。证据 docs/evidence/gc-observer-controls.json。

第一轮 Linux PR source 失败时，coverage 与直接 push 全过。记录必须携带文件名中的套件标签；同一引擎/场景会出现两份完全不同结果。镜像/CPU/事件同时变化不能识别单一原因。主 native 控制也并非逐项回收，不从合并错误块反推逐项数值。下一轮 href 清理必须同时运行相同包装而不清理的控制；双方都回收时不能宣称 href 是根因。

扩展配对两轮都失败：清理 href 与配对不清理分支均保留，不支持将清理当作充分修复。引用关系日志须在单独执行中保存；不能用日志改变时序后的通过覆盖原失败。原记录与日志记录分目录，记录每次回收对应文件名，完整压缩图保留原文件名。

1e9da66 普通门禁五/六项失败，独立 Firefox 日志版却全过。日志开销、引擎并发和独立执行共同变化，不能拿日志通过认定根因。归档全部非图条目、CRC/SHA256 与 ZIP 索引，不下载和声称归档约 1GB 的通过图。移除高开销采集回到 b746718，保留普通失败与仍开放的独立缺陷。

零回收请求的补充观察必须在新 owner/额外 GC 之前，分别记录入口、微任务及任务边界。主结果已缓存且不替换；入口可能已在模块/命令边界后回收。WeakRef 的单个 job 保活、自然 GC 与任务顺序均是限制，不能把延迟样本当修复或直接认定具体回收来自何处。

31e2952 在零新 GC 的一次任务边界后仍保留，不支持用延时补丁。实际 Firefox 验证 MOZ_CC_DISABLE_GC_LOG=1 可只生成 CC 图；本地默认运行配置不允许写图。先单独控制写图配置，不改变三引擎并发；仅控制仍失败时才加 CC 日志。原正常门禁、控制和日志记录分目录；不在每个 GC 请求中读写文件。

20b841a 三引擎无日志的后续控制通过，CC 阶段未运行。安装版 Vitest BaseSequencer 会按缓存失败优先排序；资源测试完成顺序由第五移到第一，不据此声称精确开跑顺序。后续对照须恢复 coverage 后、source 前的 results.json 并核对 SHA，保留相同 package script，先同配置重跑再改单一配置。不能归因于此前日志或 sandbox 开关。
