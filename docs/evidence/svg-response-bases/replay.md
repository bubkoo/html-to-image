# Final SVG response addresses define file-relative styles

The HTTP loader previously returned only bytes. A redirected SVG therefore retained the pre-redirect request address as its document base. Native Chromium resolves file CSS against the final SVG address: the controlled input uses a green paint definition at assets/sprite.svg while a valid red definition exists at the wrong parent address. Previous export was red, native source green. Firefox/WebKit file CSS remains inactive and its explicit purple fallback must be preserved.

Keep each resource's final response address with the same cache key as its bytes, while preserving the Blob-returning load contract and stable pending Promise. Custom Blob resolvers have no response-address contract, so they keep each requested address even when sharing the same Blob. Query-omitting legacy caches associate metadata with the bytes actually reused. Clearing the loader clears this metadata; a late pending fetch cannot restore it after clear. SVG scopes use the final address and register it as an alias for references and cycles.

An injected cache-busting nonce is transport metadata. Remove only that owned nonce from the final document identity (restore caller-provided values); preserve other response query parameters. Normal non-redirected resources retain their original semantic address. The final-address tests use real one- and two-hop HTTP redirects with and without cacheBust, with paired direct controls, native before/after screenshots, exact full RGBA and independently authored references.

## Remaining native differences

The separate real iPhone observation is intentionally a failing boundary, not acceptance of all SVG paint. With external-symbol gradient definitions, relative/absolute references use purple fallback; a fragment-only #paint instead uses a blue same-name definition in the containing page. Current export incorrectly embeds green/red definitions from the SVG file. A same-fragment definition nested in the symbol was also observed separately; it remains purple in that controlled scene. Flat green and yellow geometry/color controls and source before/after equality pass. Desktop WebKit's qualified paint behavior differs from this physical iPhone's behavior.

The private clip hit-test experiment distinguishes some declaration bases, but it has not established a universal paint-policy proxy. A visiblePainted hit test also reports a hit for missing paint in Firefox/WebKit, so it cannot prove paint availability. The private sentinel-base experiment preserves original attribute selectors, but URL normalization can lose relative-path provenance. Neither experiment is promoted to a production fix or engine-name branch.

Attribute/inline relative bases, fragment paint scope, unsupported qualified paints, redirect combinations beyond the file-style subcase, restricted CSP, opaque matching rules, HTTP file CSS/fonts and native compositor limits remain open. No npm publication or old contributor PR comment/closure.
