# V2 性能复核

2026-11-02 本机初测。基线是从公共 npm registry 下载并解包的 `html-to-image@1.11.13` UMD；候选是当前 V2 构建的 UMD。环境：macOS 26.5.2 / arm64、Playwright 1.64.1 的 Chromium、Firefox、WebKit。

使用 [benchmark-capture.mjs](../scripts/benchmark-capture.mjs) 在独立浏览器页中生成 400 个 40×20 的节点，连续导出 4 次 40×8000 PNG。每次检查尺寸和左上角像素；丢弃首次耗时，取后三次中位数。重复运行三轮，得到：

| 引擎 | npm 1.11.13 中位数范围 | V2 中位数范围 | V2 / 基线 |
| --- | ---: | ---: | ---: |
| Chromium | 181–184 ms | 209–213 ms | 1.15–1.18 |
| Firefox | 151–166 ms | 165–169 ms | 0.99–1.09 |
| WebKit | 157–162 ms | 163–164 ms | 1.01–1.04 |

第一次独立运行曾得到 Firefox 2.10 倍；随后四轮未重现，三轮稳定结果如上。V2 的阶段事件显示克隆是主要耗时段，但尚不能将 Chromium 约 15% 的差距归因于某一具体函数。此数据只覆盖无外部资源、固定布局和本机浏览器；不能推断其他 DOM、iOS 或压力下的表现。

Chromium 在垃圾回收后额外重复 20 次导出，JS 堆增量约为基线 22 KB、V2 50 KB；重复 100 次时分别约为 20 KB、45 KB，未见随次数线性增长。这是当前固定 fixture 的 JS 堆证据，不能证明其他资源或真实 iOS 无泄漏。切换前还需真实 iOS 的大图和内存压力结果。

运行方法：先 `pnpm run build`，将 npm 1.11.13 压缩包解压到临时目录，然后执行 `node scripts/benchmark-capture.mjs <解压目录>/package/dist/html-to-image.js`。脚本输出每个引擎的 4 次耗时、V2 各阶段时刻、比值及 Chromium 的垃圾回收后堆差；`HTML_TO_IMAGE_HEAP_RUNS` 可改变内存复核的重复次数。

## 继承 CSS 变量的重复序列化

2026-11-10 本机合成场景：一个根节点声明 100 个自定义属性，下面有 100 个同级子节点；直接调用构建后 UMD 的 `toSvg`，各引擎每个场景连续执行三次。复现脚本是 `node scripts/benchmark-css-variables.mjs`，可传入不同 UMD 路径对照。改动前同一个继承变量在输出里出现 101 次；改动后只在根节点出现一次。输出长度分别为 Chromium 883890→715890、Firefox 766819→598819、WebKit 888536→720536 个字符。无变量时的输出长度在改动前后相同。三次耗时的中位数在 Chromium 为 56→51 ms、Firefox 48→44 ms、WebKit 52→40 ms；这些短时数据受机器波动影响，只作为方向证据。源码与构建包的三引擎测试验证继承、覆盖及像素；Issue #542/#536 的真实重 DOM 卡顿尚未复现，不能据此宣称修复。

## 继承变量的重复读取

2026-11-10 继续复核发现：此前每克隆一个子节点，都会对同一父节点的每个继承变量再次调用 `getPropertyValue`。20 个同级子节点的受控测试在 Chromium、Firefox、WebKit 均观察到父节点的 `--fill` 被读取 21 次。按单次捕获缓存父节点的计算值后，每次不超过 2 次；修改源变量再捕获仍得到新颜色。缓存仅用于克隆阶段，随后清除。

本机 400 节点、根节点声明 300 个变量的 JPEG 合成场景，修复前后不同轮次的 Chromium 稳态约 224→212 ms、Firefox 225→219 ms；变化不大且受运行波动影响。把相同变量声明在 `documentElement` 的独立页面对照中，npm 1.11.13 与本候选的稳态分别为 Chromium 314–323 与 214–215 ms、Firefox 240–244 与 220–222 ms。旧版在仅捕获根节点声明变量的场景里较快，是因为全局属性名缓存没有纳入那些变量；不能把漏掉样式的结果当成等价性能基线。真实 Issue #542/#536 的 DOM、资源和浏览器版本仍缺少复现，尚不能判定冻结问题已解决。
